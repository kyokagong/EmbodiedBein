# UFO 交互环境关闭与切页资源回收

2026-10-18（Asia/Shanghai）。对应[设计24](../design/24-ufo-live-simulation-validation.md)。用户反馈页面缺少明确关闭入口，切页后后台仍运行。本次已部署关闭生命周期修复；无 Git 提交、无模型训练或 z 修改。

原实现卸载时只尝试发送 WS stop，随后立即关连接，无法确认命令接收；stop还会进入录像收尾。初始化、断流、排队阶段受控制按钮状态限制，也没有遗留会话管理入口。检查当时四张GPU已空闲，不能据此否认清理机制的缺口，也不把已退出容器说成仍占用GPU。

## 关闭行为

- 页面顶部常驻“关闭交互环境”，不依赖推流就绪或任务控制状态。调用所有者专属关闭接口，经现有 Job cancel→ebd 确认容器删除后才显示资源释放。排队、初始化、运行、断流和录像收尾均可关闭；重复关闭终态返回原结果。
- 站内切页/切换会话先等待关闭确认，失败保留当前页并允许重试。刷新/关页直接发 cookie keepalive 关闭请求，不受页面 AbortController 或 WS状态影响；返回 BFCache 页面仅刷新状态，不恢复已关闭会话。
- 创建响应尚未返回、页面不知道 Job ID 时，立即按既有幂等键关闭，不等待可能已丢失的响应。创建和关闭用相同的 PostgreSQL 事务 advisory lock；关闭先到则记录审计取消标记，晚到创建返回409；创建先提交则查出并取消对应作业。范围绑定用户和 native-live 操作。
- 活动环境列表只显示当前用户最多50个未终止交互会话，可以重连或关闭。晚到创建/轮询响应不会恢复已关闭环境或覆盖新会话。
- “结束并保存录像”保留正常收尾语义；“关闭交互环境”优先释放计算资源，只保留已落盘记录。关闭时未落盘的轨迹/完整录像不补造，部分产物标 complete=false。已确认删除后，诊断文件损坏单独报收集错误，不能回滚取消状态；未确认删除仍返回503，不显示已关闭。

## 复核与检查

第一轮核对作业所有权、终态幂等、初始化/排队关闭和真实容器删除。第二轮补齐创建响应丢失、取消标记的事务顺序、路由失败留页、旧响应覆盖新状态；独立复核发现部分归档异常会回滚已确认取消，已用失败检查复现并修复。第三轮在实际页面验证按钮、切页、两种刷新和真实PG并发，随后逐Job核验容器与GPU释放。

相关后端88项、前端67项、Vue类型检查、Vite构建通过；新接口/检查Ruff通过。原模型、任务镜像及Rust执行路径未更改，未因这次生命周期修复重复训练或跑质量评估。

边界：keepalive仍依赖浏览器实际发出请求和网络可达；进程崩溃/断网时仍由现有worker就绪后15秒租约及作业总超时兜底，初始化阶段不能承诺15秒内回收。永久断网、浏览器强杀和初始化卡死未做本轮实机故障注入。正常切页、刷新、初始化主动关闭及创建请求竞态已验证。
