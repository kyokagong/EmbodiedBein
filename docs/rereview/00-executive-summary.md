## 2. 初版重设计（docs/redesign）的主要遗漏与缺陷审查

在初版重设计草案中，虽然成功收敛了产品边界，但在工程落地和用户真实体验层面存在以下 **10 大关键遗漏与缺陷**：

```
                    初版重设计草案主要遗漏剖析
┌──────────────────────────────────────────────────────────────┐
│ 1. [本体] 多 URDF 变体丢失，无法满足 BHL 的 4 种形态需求         │
│ 2. [本体] 3D 资产静态路径映射缺失，Three.js 无法安全跨域取 mesh │
│ 3. [数据] 44GB 大数据集下载未设计异步任务生命周期与断点容错    │
│ 4. [数据] 缺少下载前的磁盘配额预检（statvfs），极易撑爆宿主磁盘│
│ 5. [环境] 忽视 Isaac Lab 对 Vulkan/EGL/驱动版本的要求，缺少诊断 │
│ 6. [训练] Ray 默认端口 6390 冲突，无法支持 4 卡拆分多任务并发   │
│ 7. [训练] Hydra Overrides 缺少语法预检，参数笔误导致秒退无提示 │
│ 8. [模型] 缺乏对 run 产出多个 checkpoint 的挑选与自动注册机制   │
│ 9. [模型] 血缘图退化为单链，丢失「本体+数据+镜像」多父节点关系 │
│ 10.[系统] 容器 root 写入导致宿主文件权限被锁（Permission Denied│
└──────────────────────────────────────────────────────────────┘
```

## 3. 本次再审（docs/rereview）的核心补强与设计突破

### 补强 1：本体多 URDF 动态解析与 3D 深度交互
- 解决 BHL 仓库内 `humanoid_22dof.urdf`、`biped_12dof.urdf`、`wbc_22dof.urdf`、`fixedhand_10dof.urdf` 的并存问题。
- 后端提供安全受控的静态资产代理接口 `/api/v1/embodiments/:id/assets/*`，前端 Three.js 可无缝加载相对路径网格。
- 提取 Joint 层次结构与限位（`lower`/`upper`/`effort`），提供关节滑杆，可在 3D 画布中直接预览机器人姿态与自由度。

### 补强 2：数据接入异步下载引擎与大目录高性能浏览
- 构建具备完整状态机的后台下载引擎（`pending` → `downloading` → `extracting` → `validating` → `ready` / `failed`）。
- 支持 Hugging Face 数据集（支持配置全局或按次 `HF_TOKEN`）与 HTTP URL 流式下载，带实时进度（速度、已下载字节、ETA）。
- 引入下载前磁盘配额预检（剩余容量检查，阈值警告）。
- 针对 44GB、数万文件的大型数据集，采用后端分页懒加载文件树 + HTTP Range 视频流媒体播放。

### 补强 3：环境模块「GPU / Sim Driver Doctor」与镜像管线
- 引入环境自检 Doctor：一键探测 NVIDIA Driver 版本、CUDA 版本、`nvidia-container-toolkit`、Vulkan ICD 支持与 EGL 无头渲染能力。
- 镜像管理支持 Docker 守护进程实探、Tag 自动解析 Digest 短码、拉取进度感知，并在训练提交时绑定 Digest 防止镜像漂移。
- 规范化配置 Isaac Lab Nucleus 共享资产缓存目录挂载，避免重复下载仿真资产。

### 补强 4：RLinf 训练编排的工业级多卡与容错闭环
- **Ray 端口自适应隔离**：根据 Job ID 动态分配 Ray 集群端口（`6390 + offset`），解决 4 卡上并发运行两个 2 卡任务时的端口碰撞问题。
- **Component Placement 智能计算**：根据选择的 GPU 数量（1/2/4 卡）与训练模板类型（PPO vs SFT），自动计算生成合法的 `cluster.component_placement`。
- **Hydra Overrides 实时预检与命令行预览**：提供配置语法校验，生成等价的纯命令行与单机调试 `docker run` 脚本。
- **实时日志环形缓冲区（RingBuffer）与 tfevents 提取**：保障高并发日志输出不卡死前端，实时绘制 reward/loss 标量曲线。

### 补强 5：模型基座与产物双轨管理 + DAG 多维血缘图谱
- **双轨录入**：支持磁盘本地基座模型（Base Model）录入，以及训练产物（Trained Checkpoint）录入。
- **双模式注册**：训练详情页实时扫描 `output/checkpoints/` 列出所有 step 权重，支持用户「一键勾选注册」，同时支持在新建训练时开启「成功后自动注册 latest checkpoint」。
- **真实 DAG 血缘图谱**：清晰呈现 `(本体代码) + (数据集) + (基座模型) + (训练镜像)` ──[训练任务]──> `(产出模型)` 的全要素血缘网络。

### 补强 6：元数据与存储权限严密设计
- 给出清晰规范的 PostgreSQL 表结构定义，抛弃繁重的历史过渡字段。
- 制定严格的路径安全白名单策略（默认允许 `/data/kk` 与 `/var/lib/eb`）。
- 容器动态运行时注入 `--user $(id -u):$(id -g)` 或统一宿主 UID 映射，确保训练产物文件在宿主机上可自由读写与清理。

## 4. 实施落地收益

通过本次全面再审方案的实施，平台将达成以下核心收益：
1. **认知负荷降低 80%**：使用者无需理解复杂的本体环境契约、五层门禁、CAS 哈希和数据漏斗，直接按日常科研习惯（选代码目录、选数据集、填参数、跑训练、看曲线、存模型）操作。
2. **训练可靠性提升 100%**：彻底消除 Ray 端口冲突、Hydra 覆盖笔误、镜像 Tag 漂移和容器写脏代码仓的工程隐患。
3. **资产管理完全可溯**：每一次训练跑出的权重，都能 100% 精确追溯其使用的代码版本、数据集切片、基座权重和训练超参数。
