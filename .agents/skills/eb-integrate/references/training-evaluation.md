# 新本体与新模型的训练、评估闭环

接入涉及训练或评估时必读。目标是先证明流程可执行，再用任务质量和训练趋势决定是否值得扩大；在实测安全范围内充分使用本机 GPU。以下代码路径从仓库根目录算；本文是开发操作要求，不代表已有通用自动早停或多卡能力。

## 1. 对照设计，冻结实验条件

先读 [模型与训练](../../../../docs/design/04-model-training.md)、[评估与交付](../../../../docs/design/05-evaluation-delivery.md)和[工作台](../../../../docs/design/07-workbench-api.md)，再选对应本体/算法设计。当前实现和运行证据查 `docs/progress/`，不能将某个模型的四卡结果推广到其他 recipe。新本体、模型、算法的具体接入仍按本技能相应专题执行。

扩容前明确下列信息；动作/标定语义、评估判据、预算或 step 含义不能推断时询问用户，期间完成不依赖答案的梳理与实现。

| 固定项 | 必须明确的内容 |
|---|---|
| 兼容性与身份 | 来源/许可、资产和接口版本、Task、训练/评估 Profile、recipe、数据/基座模型、processor/norm、代码内容快照与镜像 digest；新本体核对关节/frame/单位/频率/增益/相机/动作解码 |
| 实际训练量 | step 是 optimizer 更新、learner 联合更新、epoch 还是环境步；记录 runner 计数与真实更新计数的对应关系、梯度累积、有效 batch、rollout 长度、环境数、累计样本/transition 数 |
| 决策协议 | 快评间隔 K、冻结 validation case/seed/重复次数、指标方向/单位/阈值、首次快评、最小观察窗口、允许热身预算、无改善耐心窗口、硬停止条件、最终 acceptance Suite |
| 资源与时限 | 可用 GPU 及每卡角色、CPU/RAM/shm/磁盘与 I/O；总墙钟/更新/费用预算包含 probe、排队、录像、评估、保存与分析；同时限定调整轮数，不能无限试错 |
| 证据策略 | checkpoint 保存频率/完整性/恢复模式、快评与最终评估的录像覆盖、曲线/原始数据、可访问的报告与媒体入口、存储预算与保留方式 |

先查源码和当前 schema，确认这些条件由哪些参数或执行步骤兑现，不将上表写成臆造的 API 字段。数据按原始 episode/take/session/subject 等祖先分组后冻结 train/validation/acceptance；切窗、镜像、重定向副本和近重复不能跨 split。norm、量化 calibration 与拟合只能使用允许的训练输入；acceptance 不参与调参或候选选择。已发生泄漏时，删除训练 episode 再用受污染权重评同一批不能恢复独立性；回溯干净基座/完整 checkpoint 或重训，并派生真正未见的 holdout，保留旧报告与污染范围。

## 2. 默认训练阶梯：100 → 500/1000 → 5000–10000 steps

仅扩展评估能力时使用已有冻结模型/推理包，验证推理、独立评估、图表/录像、失败/取消与证据保全，不另开训练或补训练恢复。以下训练更新、恢复和固定 step 决策用于训练路线。

训练按以下三档推进；默认 step 指实际完成的 optimizer 更新或 learner 联合更新，先核对实际训练器计数，不能直接用 rollout 长度、采样轮数或环境步代替。

| 阶段 | 默认终止目标 | 放行条件 |
|---|---|---|
| 流程测试 | 100 steps | 持续真实更新，无运行错误、NaN/Inf 或 OOM；checkpoint 回读/恢复、独立快评、图表和录像链路完整。此阶段不要求任务指标已经改善，即可进入下一档趋势测试 |
| 小规模趋势测试 | 500 或 1000 steps | 用冻结 validation 与基线/100-step 结果比较，结合训练曲线的前后窗口、波动和任务指标，验证改善持续且无硬停止项；没有改善或证据不足则分析调整，不进入正式训练 |
| 正式训练 | 5000–10000 steps | 趋势测试已证明指标改善，资源和剩余预算允许，周期快评/恢复已验证；正式训练仍逐区间决策，退化或无改善达到停止条件时提前终止，结束后独立验收 |

500 与 1000 是可选的趋势测试目标，不要求两档都跑；500 steps 已有足够改善证据时可进入正式训练，窗口不足时在预算内观察到 1000。5000 与 10000 同样是需预先冻结的目标，不能因属于“正式训练”而无条件跑满或自动追加。阶段目标与快评间隔 K 分别设置：进入 500/1000 或 5000–10000 steps 后仍按 K 快评，不只在阶段末评估。

同一实验兼容恢复时，目标按累计更新计数：100 → 500 表示再训练 400 steps；改变配置而重启的新实验从自己的实际计数开始，报告源阶段和初始化语义。阶段升级不强制改变 GPU/batch。已完成且配置一致、证据完整的阶段直接复用；16/24 steps 等极短执行仅用于必要的依赖探测、容量 probe 或故障复现，不作为反复追加的训练阶段，也不能替代 100-step 流程测试。这些是默认训练指导；任务专属设计有不同预算/配置约束时先说明并核对，不用修改设计或绕过模板校验套用数字。

100-step 流程测试核对：

1. 预览/提交的同一 JobSpec，目标镜像中的配置、loader、processor/norm、forward/backward；闭环任务实际 reset/step 和动作语义。需要训练的路线须证明参数确实更新，不能只看 loss 有输出。
2. 完整 checkpoint 原子提交及回读；核对 optimizer、scheduler、RNG、适用的混合精度 scaler、sampler/算法状态和实际恢复后的计数。只有权重的路径标 `warm_start`；环境/rollout 不可恢复时不能标 `exact`。
3. 由完整冻结 checkpoint/模型版本启动独立快评，回收逐 case 结果和真实录像，验证成功/失败函数、报告完整性、媒体可播放及指标曲线可见。纯离线指标只证明 `offline_eval`，不代替机器人闭环能力。
4. 验证失败、取消、资源释放、最后完整产物保全和周期评估衔接；取消并不保证自动保存 checkpoint。若没有受验证的恢复路径，不以杀容器后重启实现“暂停”。

有尚未补齐的周期评估、可视化、模型桥或恢复能力时，先通过现有 adapter/runner/collector/API 补实现并做最小行为验证，再扩容；记录缺口，禁止直接启动长训后承诺补证据。阶段一不要求随机初始策略已合格，但要求链路和指标可信；保留未训练/基线及短训后的同条件快评，便于比较。

## 3. 三个训练阶段的 GPU 资源与扩容

- 经 Doctor、现有 Job/Run 和目标镜像 probe 核实实际可用卡及外部占用；默认整卡独占，不动其他作业、不伪造 GPU 证据。四张 24GB 卡不能按一张 96GB 卡估算。
- 区分多卡 learner（DDP/FSDP）、单 learner 多卡 env/rollout、独立 seed 训练和 case 并行评估。只有 recipe 已验证的拓扑可用；单卡算法可在预算内并行独立实验，但不能称梯度同步训练。独立实验须分别登记，不能为了占满卡增加未授权实验。
- 对支持的卡数/拓扑逐级做有限 probe，测真实组合的加载、更新、采样、权重同步、checkpoint 保存及录像峰值。逐卡记录物理 UUID/索引→容器逻辑设备→worker/rank 映射；placement 不得越过资源租约。核对 RAM/shm、渲染/编码、磁盘、数据加载与 CPU 瓶颈，保留对应设计要求的余量，禁止靠反复 OOM 搜索上界。
- 比较同条件 transitions/s、有效样本/s、learner updates/s、评估 cases/s、阶段墙钟及每卡显存/利用率；选择预算内有实际加速且学习语义合理的规模。卡更多却更慢时先定位同步、I/O、加载或渲染瓶颈，说明闲卡原因。
- 扩容显式核对有效 global batch、microbatch、累积、world size、LR、rollout 和更新/采样比。离策略算法还需 replay 容量、留存/来源比例、样本重用及覆盖；更多 env 不等于更多优化。若改变算法配置或拓扑，派生新 spec 并标明 warm start/可支持的恢复语义，不静默改变 batch 或冒充 exact resume。
- 训练与快评并发仅在分别准入、保留评估资源且训练在决策点可停住时采用；所有卡用于训练时，采用已验证的分段结束/保存/释放→评估→决定→续训流程。加速最终评估可用更多空闲卡分 case，每例只分配一次；固定逐 case RNG/超时/判据，核对单卡与并行结果等价，再按逐例原始结果完整汇总，不能平均 shard 成功率。

[BFM 四卡设计](../../../../docs/design/16-bfm-zero-data-and-4gpu-training.md)是单 learner 加三张采样卡的具体实例，其 batch、更新/采样关系及[后续参考设计](../../../../docs/design/18-bfm-reference-prior-and-g1-rpo-retarget.md)不作为其他算法默认。资源增加后先完成一个区间的快评，再扩大下一档。

## 4. 固定 step 快评与继续/停止决策

每到实际计数的 K 个 step：**完成 checkpoint → 冻结快评输入 → 独立评估 → 联合分析训练趋势与任务指标 → 写结论 → 决定下一段**；最后不足 K 的区间也做快评。保存间隔须与评估点匹配，并满足实际模板校验。训练器内置 validation 可以辅助诊断，但不能替代独立评估。

决策前不启动下一段或预提交无条件串联的长训。异步评估必须核对源 Run、step、模型与 plan hash；旧 step 的结果不能放行当前区间。等待评估不应持续占用闲置训练资源，是否可释放/恢复以已验证路径为准。

先核实：当前评估入口是否允许冻结运行中的 checkpoint，还是只接受已成功结束 Run 登记的 ModelVersion；runner 是否可在边界等待决策；恢复是否完整，且在新 Run 继续正确累计计数。只有终态入口时可分段正常结束，再通过受支持的恢复提交下一段。**分段和恢复也不支持时，先补能力，不能用从头或权重 warm start 冒充同一训练的每 K step 续训。**所有重启都创建派生 Job/Run；不能凭设计文档宣称当前自动闭环已实现。

| 结论 | 可观察条件与动作 |
|---|---|
| 继续下一段 | 快评/媒体完整、无硬停止项、预算足够，主指标或预先指定的诊断指标在观察窗口内支持继续；允许早期零成功的条件必须在热身预算与观察规则中预先限定 |
| 停止并调整 | NaN/Inf、物理越限等触发固定硬停止条件；任务指标显著退化、饱和/跌倒异常增加，或超过耐心窗口无改善；保存证据、提前终止训练，先分析原因再做有界调整 |
| 等待证据 | case/媒体缺失、infra failure、checkpoint 不完整、数据泄漏、指标语义未知或结果来自旧 step；停在决策点，先修证据/实现，不能将未知当改善继续 |
| 结束本轮 | 达到冻结目标或预算；保全已完成证据，按规则选候选，独立验收；预算不足不追加未经授权的训练 |

task failure 不作为基础设施重试；infra failure 只对固定 case 做有界重试并保留 attempt，不能用反复换 seed 隐藏失败。新模型允许有界热身，不能仅因首次低成功率永久否定路线，也不能因 reward 增长忽视质量退化。

停止时核对目标 Job/Run，通过平台取消入口终止需要取消的运行，验证容器实际退出、资源释放和最后完整 checkpoint。取消失败或保存不完整如实报告；不改 SQL 成功状态，不覆盖旧产物。按输入/关节与单位→processor/norm/动作解码→训练与评估环境差异→梯度/奖励与 loss 分项→采样更新比例和资源瓶颈检查原因。区分事实、假设和缺失指标；保持冻结 validation 条件做最小单因素对照，新配置/数据/代码派生新版本，回到小样本验证。

## 5. 每次训练与评估的可视化

**训练必有真实指标时序分析。**复用工作台训练/Run 页面和现有 Chart、日志/metrics/Artifact 通道；同时保留可分享的曲线与原始数值，不只贴终值或截图。曲线按实际更新与墙钟展示，注明单位、窗口、raw/smoothed、缺失/异常点和来源；比较区间起止、窗口均值/分位/斜率、尖峰及离散程度。恢复/配置变化处标注新 Run 和计数偏移；不将 warm start 拼成连续恢复曲线。

按算法挑选实际存在且有决策价值的指标，并核对指标实现：

- 学习：total/各分项 loss、LR、梯度范数和裁剪前后/裁剪比例、参数更新量；SFT 分 mask/chunk/来源的误差，RL 的 reward 分项、return、episode 时长、KL/entropy 等。
- 行为与数据：真实成功/终止原因、动作饱和与 requested/applied action、越限、跟踪误差、各来源实际采样、有效样本量；离策略的 replay 和更新/采样比例。无关算法的指标不强加，关键诊断缺失时补采集或明确证据不足。
- 资源与耗时：每卡显存 allocated/reserved/实际峰值、GPU、RSS/RAM/shm/I/O；更新、采样、同步、保存、评估/录像的阶段耗时。嵌套/重叠时序不能重复相加；训练 episode 均值不能标为独立评估成功率。

**每次评估必有图表和真实录像。**展示逐 checkpoint 主指标趋势、完整案例分母/成功率区间、失败原因分布和逐 case 指标；区间按冻结 Suite 的置信要求计算，相关样本按 group 聚合，不能假定重复窗口独立。录像绑定模型 hash、Run/step、Suite revision、case/seed/重复编号、终止原因及指标时间轴。快评小集合默认每例录制；正式评估事先固定媒体覆盖规则，覆盖成功及失败类别与主要失败原因，用户/Suite 要求全量时全部录制，不能只展示好看的成功片段。

逐个核对所需视频的文件/hash、可解码、时长/FPS、case 映射和页面可播放；截取摘要保留完整原片及时间定位。某类实际没有出现时写“本轮无成功/失败案例”，不伪造对应录像；离线评估无闭环录像时标明范围及未满足项，不宣布闭环接入完成。缺失/损坏媒体标 `unavailable`，不补造、不静默删 case；必需证据未齐保持 incomplete。参考动作/数据回放不当作策略在物理中成功的录像。

checkpoint 默认只保留最新完整版本；快评前通过受管 Artifact/租约保全被评模型、processor/norm 与报告媒体，最佳候选同样保全，不能等 GC 后再找。若当前 runner 的清理不尊重这种保全，先补链路或用不会发生并发清理的受验证分段流程。视频、tfevents、轨迹和大文件解析/流式服务走 ebd/任务容器，FastAPI 只编排元数据；不另建常驻 TensorBoard/媒体服务替代平台证据。

## 6. 每个区间的状态报告与最终验收

每次决策留下以下六项；它们是报告内容，不是新增 API schema：

1. **身份与训练量**：TrainJob/Job/Run、配置/输入/代码/镜像 hash、区间实际起止更新、累计样本/transition 与墙钟、checkpoint step/hash/恢复模式。
2. **训练趋势**：原始数据与曲线引用、关键指标前后窗口和异常、学习与行为是否一致、缺失诊断。
3. **独立快评**：Suite/plan hash、planned/completed/valid/invalid/infra_failed/cancelled、成功率分子/分母及区间、主指标、失败原因、成功/失败录像索引及缺失项。
4. **资源效率**：逐卡角色/峰值、实际吞吐和时间分配、CPU/RAM/shm/I/O、采样更新比例及相比前一档的有效加速。
5. **结论与下一步**：继续/停止调整/等待证据/结束、依据与不确定项、剩余预算、下一段目标或最小对照实验；不能只写“loss 下降，继续”。
6. **证据保全**：受管 Artifact/ModelVersion/报告/媒体引用、完整性、保留方式与用户可访问入口。

最终按冻结 validation 规则选择 best，latest 另行标注；候选固定后才运行独立 acceptance，不把周期快评当正式验收。使用准备交付的实际推理包另做对应评估，导出/量化/目标性能有自己的证据；sim2sim、目标设备和真机未覆盖时分别标明。训练执行成功、产物完整、模型 `qualification=pass|fail|incomplete` 与目标可部署是不同结论。

至少三轮复核：①设计/本体语义/来源与 split；②GPU、step、周期决策、恢复/取消/失败与预算；③时序分析、全部计划 case、成功/失败媒体和证据入口。记录发现、修正与实际复测结果，更新进度；不为通过验收降低阈值或改设计。
