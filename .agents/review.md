# 开发技能复核记录

日期：2026-09-24。范围：仓库开发工具、接入/排障/开发技能和根目录操作入口；不修改产品实现或设计真源，不提交 Git。以下是文档整理的检查记录，不是平台运行验收。

## 第一轮：设计与当前实现对照

对照 `docs/design/01–06`、环境目录设计、当前路由、Makefile、Dockerfile、adapter、调度、产物收集与测试入口，并做无新技能的只读场景基线演练。

发现并修正：旧 AGENTS 的“仅 BHL 骨架”“任务镜像均为占位”“全部路由集中”“无 GPU 默认四卡”“血缘未接”“只加 adapter 即可接新栈”不符合当前代码。保留原硬约束及可配置存储根，增加技能入口和实际能力证据口径。

## 第二轮：四类接入的端到端遗漏

使用新接入技能复测非 BHL 本体、外部只读数据/模型、新 RLinf 算法，并加入任意 HF URL、HTTP 数据包、修改已发布接口三个边界场景。

补充/修正：

- 本体接口、Task、EnvironmentProfile、模板/Suite 是不同对象，不能只做页面或 YAML。
- 普通本地 validate 默认 LeRobot v3；HTTP 下载当前拒绝，HF revision/来源受限。
- 登记外部目录不自动冻结；模型下载不代表能被 loader 消费；评估数据不可混入训练。
- checkpoint 完整性、恢复状态、collector 分支、独立评估与血缘都纳入接入出口。
- `RenderedJob` 不承载 CPU/主存字段，预算从 `JobSpec.resources` 经 orchestrator 传递。

## 第三轮：失败路径与操作真实性

复测 queued、成功无模型、沙箱拒绝 Docker socket、默认端口无响应场景；逐项核对工具源码。

补充/修正：健康检查必须查看嵌套 `ebd.ok/error`；Doctor 要检查错误详情；`ebctl ps` 的回退/退出码不足以判健康；HTTP 命令有超时，沙箱不可访问不能推断主机没 GPU。纳入主存准入、部分 checkpoint、取消、管线恢复、日志回退、前端旧构建和模型资格失败等路径。

## 第四轮：开发交接与可维护性

检查已有工作区改动的保护、迁移/旧数据、容器化验证、ToolBus 禁令、前端检查和文档入口。复用已有 Makefile/API/ebctl，不新增重复 CLI 或框架；三个技能按场景加载，四类接入细节分参考文件。

复测补充：`make migrate` 不重建独立 migrate 镜像；`0001_init` 使用当前 metadata，需同时验证空库和旧库升级；只读挂载的 Ruff 使用 `--no-cache`；工具矩阵快照不能代替权限行为测试。

## 2026-10-10：新本体/模型的训练与评估闭环

### 第一轮：设计、源码与既有指导

对照设计 04/05/07、BFM 四卡及后续参考设计，读取训练/评估请求、GPU placement、恢复限制、checkpoint 清理、collector、取消和页面入口。确认并写入：

- 四张 4090 不是共享 96GB 显存；单 learner 多卡采样、DDP/FSDP 和 case 并行是不同能力，不继承其他 recipe 的验证状态。
- 加 env 会改变采样与更新比例；扩容须测真实组合、保存/录像峰值和有效吞吐，不以 GPU 忙碌度推导学习改善。
- 部分评估入口只接受结束 Run 登记的模型；恢复也有模板与指纹限制，不能将设计中的周期评估当作当前通用能力。

### 第二轮：三组基线与带技能复测

先用原技能做只读基线，再用修订技能让独立测试者处理同样请求。基线已能保留独立评估、数据隔离和恢复边界；本轮补充周期放行条件、时序分析内容、证据保全和固定的区间报告结构，没有将正确的基线判断记录为失败。

基线原文摘录：“若只能终态收集，就分成 100 更新的派生 TrainJob”“时序图分别展示训练指标与逐 checkpoint 评估结果”“缺口未验证前，最多推进一个成功的 100 更新阶段及其评估”。对应进一步检查：分段是否真的能完整恢复；图表是否含原始数据及窗口统计；扩大一个区间前是否已证明完整闭环。

| 场景 | 修订后的实际方案检查 |
|---|---|
| 四卡、两次更新已跑通，快评 0/12 且 reward/动作饱和增加 | 停在决策点先诊断；区分任务失败与 infra；只有预先限定的有界热身规则和证据支持才继续，不直接扩容；无成功案例如实注明 |
| 新机械臂/VLA，另一个 Job 占两卡，8/8 后发现泄漏、坏视频和缺 optimizer | 不抢占、不开启未验证 DDP；停止扩容、保留污染报告，回到干净输入与独立 holdout；坏媒体 unavailable；权重不能冒称完整 resume |
| 四卡训练独占，仅终态模型可评估，周期恢复未验证 | 先补正常结束后的完整恢复/计数/保全，验证后分段释放资源再评估；不预提交后续长训，不承诺两小时必达 1000 更新 |

以上三组带技能演练均形成正确的继续/停止/等待条件及可追溯证据方案；它们是文档应用验证，没有实际执行作业。

## 2026-10-12：三档训练步数指导

范围：按用户要求明确 100 steps 流程测试、500 或 1000 steps 趋势测试、5000–10000 steps 正式训练；更新技能入口、闭环参考及 AGENTS 默认流程，不修改训练配置、代码或设计。

1. **计数与设计复核**：默认按真实 optimizer/learner 更新计数，不能把 rollout 长度、采样轮数或环境步直接作为阶段预算；兼容恢复按累计目标，100→500 新增 400 更新。保留专属设计、实际模板校验和资源预算约束。
2. **行为基线与复测**：原指南的基线答复为“技能没有默认更新数”，无法从 100 次无报错给出默认下一档。修订后三个只读场景分别得到：100 次流程完整但质量未改善→进入 500 次趋势测试；500 次仅 loss 下降、充分窗口内任务指标未改善→停止分析调整；500 次持续改善且条件完整→进入 5000 次正式训练，不强制再跑 1000。三个场景均不追加无必要的 16/24 次短测，并区分阶段目标与快评间隔 K。
3. **入口与静态复核**：技能、参考和 AGENTS 的三档目标一致；仅评估路线不要求训练，正式训练仍保留周期快评/可视化/早停及独立验收。已有无网络、只读测试容器中的官方技能元数据及 13 份 Markdown、52 个本地链接检查通过，本次差异与新文件 whitespace 检查通过。
