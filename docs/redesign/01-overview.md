# 01 · 产品定位与信息架构

## 1. 这版平台是什么

EmbodiedBein 本版是一台 4×RTX 4090 单机上的 **RLinf 训练工作台**：

1. 把本体代码放到指定路径，平台扫描并展示 3D 资产
2. 把数据从指定来源拉到指定目录，并可翻看内容
3. 管理 Isaac Lab 仿真环境与训练镜像
4. 填 RLinf 需要的配置，提交训练
5. 看当前/历史训练任务的日志、指标、结果
6. 登记基座模型与训练产物，并保留血缘

不做：评估体系、真机部署、Agent、对外 Showcase。

## 2. 谁在用、每天干什么

只有操作者自己（单用户）。同事观察、Agent 值班不在本版。

每天的主路径只有一条：

```
选本体 → 确认环境镜像 → （可选）挂数据/基座模型 → 填 RLinf 表单 → 跑起来 → 看曲线和日志 → 产物进模型目录
```

总览的职责是回答：现在有没有任务在跑、四张卡谁占用、磁盘还剩多少。

## 3. 导航（本版唯一信息架构）

```
总览
本体
数据
环境          ← 新建。Isaac Lab + 镜像
训练          ← 原「实验」+「提交任务」+「队列」
模型

设置不进主导航，放侧栏底部：允许路径前缀、RLinf 仓路径、默认镜像。
```

二级结构统一为 **列表 → 详情 → 动作**。训练的「动作」是新建；数据的「动作」是下载；本体的「动作」是登记路径；环境的「动作」是拉取镜像。

路由建议：

| 路由 | 页 |
|---|---|
| `/` | 总览 |
| `/embodiments` | 本体列表 |
| `/embodiments/new` | 登记路径并扫描 |
| `/embodiments/:id` | 本体详情（3D + 扫描结果） |
| `/data` | 数据列表 |
| `/data/new` | 下载到目录 |
| `/data/:id` | 内容浏览 |
| `/envs` | 环境：仿真栈 + 镜像 |
| `/train` | 训练任务列表（默认页） |
| `/train/new` | RLinf 表单 |
| `/train/:id` | 日志 / 指标 / 产物 |
| `/models` | 模型列表 |
| `/models/:id` | 详情 + 血缘 |
| `/settings` | 路径与配额（侧栏底部，非第六业务模块） |

## 4. 模块怎么咬合

```
                元数据（Postgres）
                        │
     ┌────────┬─────────┼─────────┬────────┐
     ▼        ▼         ▼         ▼        ▼
   本体      数据      环境      训练      模型
   path     path     image     mounts    path
     │        │         │         │        │
     └────────┴─────────┴────► 容器挂载 ───┘
                              /workspace/*
```

训练任务是唯一的「运行时实体」。它引用：

- 1 个本体（必填，只读挂载代码与资产）
- 1 个训练镜像（必填，来自环境模块）
- 0..1 个 Isaac Lab / RLinf env 配置（表单选择）
- 0..n 个数据目录（只读挂载）
- 0..n 个模型目录（基座只读；本次输出目录可写）

不要求先有「已发布本体环境」才能提交。

## 5. 成功标准（本版验收）

打开工作台后，不需要理解「契约 / 本体环境 / 四元组 / CAS」，就能完成：

1. 登记 `/data/kk/Berkeley-Humanoid-Lite`，看到 URDF 3D
2. 把一份数据下载或登记到 `/var/lib/eb/datasets/...`，能列出文件或 episode
3. 在环境页看到 `eb/rlinf:...` / `eb/isaac-lab:...`，能触发 pull
4. 用模板 `berkeley_wbc_ppo_mlp` 填 GPU 数、并行环境数、epoch，提交
5. 在训练列表看到 running，点进去有日志和指标
6. 结束后在模型页看到新权重，血缘指向这次训练和基座（若有）

## 6. 明确不做什么（防膨胀）

- 不为「将来接第二套仿真」先抽象 Env Provider 插件框架
- 不把 Hydra 全量 200+ 字段做成表单；模板 + 常用字段 + YAML 覆盖
- 不把 git worktree 冻结当成接入本体的前提（默认挂已登记路径）
- 不在本版恢复评估导航，即使 G1–G5 代码还在
