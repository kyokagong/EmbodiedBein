03 · Data

数据管理模块

你现在的数据现状是：44 GB 原始素材，最终只有 35 个可用场景，且没有一条机器人关节轨迹。 所以这个模块的第一使命不是「浏览数据」，而是让数据变得可用—— 把漏斗讲清楚，把人手轨迹重定向成机器人动作。

原始 44 GB / 18,974 文件 可用场景 35（reach 29 / push 6） 标准数据集格式 0 个 三种许可，两种含 NC 限制
词表 数据集与 G2 比对的是本体环境 ee_*，不是旧名契约。 Scenario 仍是数据域实体，与训练 Task 不是同一个东西。

3.1 六层数据模型

当前 /data/kk/berkeley_ego_data/ 的目录结构（raw/ → derived/ → manifests/） 已经隐含了一套分层，但层与层之间的转换逻辑埋在脚本里。平台把它显式化为六层， 每层都有明确的准入标准与可查询产物。

一个需要你决策的判断 从探查结果看，人类 ego 路径的产出率是 155,369 → 35（0.02%），而且产出的只是「场景描述」而非「动作轨迹」。 相比之下，脚本专家采集在 Isaac 里可以直接生成任意多条带真实 10 维动作的 LeRobot 数据。 本设计因此把「脚本专家采集」列为数据模块的第一优先能力，人类数据重定向作为研究性支线。 如果你的目标本来就是「验证人类视频到机器人的迁移」，那优先级要反过来——这一点请确认。

// eb-scanner：嗅探与统计的并行结构（要点）
pub fn scan(root: &Path, opts: &ScanOpts) -> Result<ScanReport> {
    let kind = detect_format(root)?;                  // 按上表优先级短路匹配，只读特征文件

    let files: Vec<FileEntry> = WalkDir::new(root)
        .into_iter().filter_map(Result::ok)
        .filter(|e| e.file_type().is_file())
        .collect::<Vec<_>>()
        .into_par_iter()                              // rayon：96 核并行
        .map(|e| {
            let h = if opts.hash { hash_file(e.path())? } else { None };
            // 视频只调用一次 ffprobe，元数据入缓存（按 path+mtime+size 命中）
            let media = if is_video(e.path()) { probe_cached(e.path())? } else { None };
            Ok(FileEntry { rel: .., size: .., sha256: h, media })
        })
        .collect::<Result<_>>()?;

    // 增量：与上次 ScanReport 比对 (path, size, mtime)，未变文件跳过哈希
    let stats = aggregate(kind, &files)?;             // 分组计数、分辨率直方图、时长分布
    Ok(ScanReport { kind, files, stats, scanned_at: now() })
}
性能预算（目标值，需实测校准） 首次全量扫描 44 GB / 18,974 文件：哈希是瓶颈，按单盘顺序读 1 GB/s 估算约 45 s， CPU 侧 blake3 远快于 IO，因此实际受磁盘带宽限制。增量扫描（仅 stat）应在 2 s 内完成。 若首次扫描超过 3 分钟，说明磁盘随机读成为瓶颈，需要调大并发度或改用顺序批读。

3.5 人手到机器人的重定向管线

这是当前数据链路缺失的关键一环：现有数据只有人手 MANO 48 维参数与物体 SE(3) 位姿， 而训练需要机器人 10 维臂关节轨迹。好消息是所需工具在你的仓库里已经存在。

  1. 提取手腕 6D 轨迹
    从 MANO 参数取全局旋转与平移，结合 egocentric_frame_extrinsic.npy 变换到世界系。 30 fps，输出 T_wrist(t) ∈ SE(3)。
  2. 尺度与坐标系对齐
    人臂长与机器人臂长比值做位置缩放；肩部原点对齐。这一步需要一份标定参数， 可复用 --camera-calibration 已有的参数格式。
  3. 逆运动学求解
    可复用 仓库已依赖 pin + pin-pink， 且 scripts/teleop/run_teleop.py 已实现双臂 IK。 把 teleop 的在线 IK 改造为离线批处理即可，含阻尼最小二乘与关节限位软约束。
  4. 限幅与平滑
    按契约的 limits.joint_pos / joint_vel 裁剪；对 20 Hz 目标频率重采样并做低通滤波， 避免生成物理上不可执行的抖动动作。
  5. 可行性校验（关键筛选）
    在 Isaac 里重放生成的动作，检查：末端是否到达目标（位置 RMSE）、是否自碰撞、是否触限。 不通过即拒绝该样本，并记录原因进漏斗。
  6. 场景重建与渲染
    物体类型/初始位姿 → 实例化 Isaac 资产；用机器人自身相机渲染 camera_top[224,224,3]， 与真实 ego 帧共同保存（前者用于训练，后者用于对照）。
  7. 产出 LeRobot 数据集
    state[10] / action[10] / camera_top / task 指令文本， fps=20，契约标记为 ec_bhl_fixedhand_10dof_v1，走 G2 校验。

诚实的风险评估 这条管线有三个不确定点：人手与 10 DOF 机械臂的运动学差异可能大到 IK 无解； 物体识别与资产映射需要额外的视觉标注； 人类操作的接触语义（抓握、施力）在无夹爪的 fixed-hand 构型上可能根本不可复现。 因此建议先在 29 个 reach 场景上做小规模验证（reach 无需抓取，最可行）， 拿到重放成功率后再决定是否投入。

3.8 版本、切片与治理

版本

  • DatasetVersion 不可变，标识为内容哈希（所有文件 sha256 的 Merkle 根）
  • 差异对比：新增/删除/修改的 episode 列表 + 统计变化
  • 被任何 Run 引用过的版本不可删除，只能 archived（数据移到冷层，元数据永存）
  • 版本上标注 compatible_contracts[]，G2 校验的结果缓存在这里

切片

  • 声明式：filter + balance + split + seed
  • 物化为 episode id 列表（轻量，不复制数据）
  • 与 EvalSuite 的 seed 注册表绑定，保证训练/评估不串数据
  • 典型切片：train、val、ood_instruction（换指令措辞）、ood_object（换物体颜色/形状）

治理

  • 配额：每个 Dataset 声明上限，超限拒绝新版本
  • 冷热分层：TACO 的 24 GB pkl 属于冷数据，压缩归档
  • 代理媒体（缩略图/HLS/proxy）可随时重建，不计入备份
  • GC 预演：先列出「将删除什么、能回收多少」，确认后执行

CREATE TABLE dataset_versions (
  id             text PRIMARY KEY,
  dataset_id     text NOT NULL REFERENCES datasets(id),
  layer          smallint NOT NULL,        -- 0..5
  format         text NOT NULL,            -- lerobot_v21 | eb_catalog | taco_raw …
  content_hash   text NOT NULL,            -- Merkle 根，不可变标识
  storage_uri    text NOT NULL,
  size_bytes     bigint NOT NULL,
  n_episodes     int, n_frames bigint, fps real,
  compatible_contracts text[] NOT NULL DEFAULT '{}',  -- G2 结果缓存
  license        text NOT NULL,
  license_flags  text[] NOT NULL DEFAULT '{}',       -- nc | attribution_required
  stats          jsonb,                             -- 分布直方图、分辨率、时长
  validation     jsonb,                             -- 规则 → {passed, severity, detail}
  parent_id      text REFERENCES dataset_versions(id),
  produced_by    text REFERENCES runs(id),
  status         text NOT NULL DEFAULT 'active',  -- active | archived
  created_at     timestamptz NOT NULL DEFAULT now(),
  UNIQUE (dataset_id, content_hash)
);

CREATE TABLE funnel_reports (
  id           text PRIMARY KEY,
  version_id   text NOT NULL REFERENCES dataset_versions(id),
  stages       jsonb NOT NULL,     -- [{name, in, out, rules[]}]
  rejections   jsonb NOT NULL,     -- {reason: count}
  sensitivity  jsonb,                -- {rule: delta_accepted}（重算得出）
  samples_uri  text                  -- 被拒样本索引（JSONL in CAS）
