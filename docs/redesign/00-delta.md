# 00 · 对照现行设计：保留、改名、砍掉

对照来源：`docs/design/`（01–13）、`docs/review/`、线上导航与页面实现。

## 1. 线上现在看见什么

登录后左侧 13 项：

> 总览 · 本体 · **任务** · 数据 · 模型 · **实验** · **提交任务** · **队列** · **评估** · **排行榜** · **部署** · **Agent** · **Showcase**

和本版目标的错位：

| 线上 | 问题 |
|---|---|
| 「实验」`/train/experiments` | 只有 id / name / env 三列空表，**不是训练任务列表** |
| 「提交任务」与「队列」拆开 | 训练被拆成三个入口，主路径不清晰 |
| 「任务」`/tasks` | 平台领域实体（Gym / Hydra 绑定），不是用户要管的「训练任务」 |
| 评估 / 排行榜 / 部署 / Agent / Showcase | 你明确本版不需要 |
| 没有「环境」 | Isaac Lab 与训练镜像散落在提交表单的 image 下拉和设置里 |
| 本体 | 已有列表 + 3D，但接入向导按「契约 / 本体环境 YAML」建模，不是「指定路径扫描代码」 |
| 数据 | 列表按六层/许可/漏斗，没有「从某处下载到指定目录」 |
| 模型 | 有列表和血缘骨架，但主存储叙事仍是 CAS，不是磁盘目录挂载 |

现行设计里「训练」其实叫实验（Experiment）→ Job → Run 三层；用户要的是**一层：训练任务**。

## 2. 词表必须先拆开

现行 12 章把「环境」用在两个完全不同的东西上，这是最大的认知税。

| 词 | 现行设计 | 本版 |
|---|---|---|
| **本体** | 机器人家族 + 外部仓指针 | **保留**。改为代码目录接入，扫描 3D 资产 |
| **本体环境** `ee_*` | obs / act / Hz YAML，Job 必引 | **降为派生快照**，不再是导航一等实体 |
| **任务** `tsk_*` | Velocity / Reach 等启动入口 | **退出导航**。Gym id / RLinf env yaml 在训练表单里选 |
| **环境**（你的用法） | 设计里没有这个导航 | **新建模块**：Isaac Lab 仿真栈 + 训练镜像 |
| **实验** | 训练的分组容器 | **改名为训练**，直接列出训练任务 |
| **RLinf `env/*.yaml`** | 登记在 Task.stack_bindings | 训练表单的「仿真任务」选项，挂在环境和本体扫描结果上 |

本版说「环境」，一律指 **Isaac Lab 仿真运行时及其 Docker 镜像**，不再指 obs/act 契约。

## 3. 保留

这些现行机制仍然对，只是收窄使用面：

- 单机 `docker compose`；任务容器由数据面动态创建，不进 compose
- 控制面 Python / 数据面 Rust；控制面不 `subprocess` 跑训练
- 外部仓 `/data/kk/Berkeley-Humanoid-Lite`、`/data/kk/RLinf`、`/data/kk/berkeley_ego_data` **只读**，平台不写入
- 训练时把目录挂进容器（只读代码/数据，可写仅 run 工作区）
- GPU 整卡调度（4×4090）
- Run 日志 + 指标曲线（现有 `RunDetail` 是最接近「看训练」的页）
- URDF / mesh 的 3D 预览
- 模型血缘边
- RLinf Adapter 边界（改输入：表单 → Hydra，而不是 JobSpec 四元组）

## 4. 改名与合并

| 现行 | 本版 |
|---|---|
| 实验 + 提交任务 + 队列 | **训练**（列表 / 新建 / 详情；队列是列表上的状态） |
| 设置里的镜像字符串 | **环境 → 镜像** |
| EmbodimentEnv YAML 手维护 | 本体扫描得到的接口快照 |
| Experiment / Job / Run 三层 UI | UI 只暴露 **训练任务**；内部仍可 Job+Run（一次尝试） |
| CAS 作为产物主存储 | **磁盘目录为真源**，元数据里记 path + 可选哈希 |

## 5. 本版不做（从导航和验收里拿掉）

不是永远不做，是**本版设计范围外**：

- 评估套件、对比、失败库、排行榜、Wilson 区间、跨域热力图
- 部署、PolicyBundle、真机放行、robot-agent
- 平台 Agent、ToolBus、Showcase
- 数据六层漏斗（155k→35）、许可传染门禁、人手重定向
- 本体环境 CRUD、G1–G5 作为提交卡口（扫描结果可展示，不阻断本版主路径）
- Isaac Lab + RSL-RL 作为与 RLinf 并列的训练栈（Isaac Lab 只作为仿真环境）
- MinIO / CAS 作为主存储；Pipeline DAG

现有代码可以留着，但前端主导航不再出现这些入口。

## 6. 三种做法（为何选现在这套）

**A. 目录型工作台（采用）**  
元数据在 Postgres，文件在磁盘，训练时挂载路径。五模块：本体 / 数据 / 环境 / 训练 / 模型。RLinf 用模板+表单+Hydra 覆盖。

**B. 只改名字**  
把「实验」改成「训练」，其余 12 章领域模型不动。便宜，但用户要的「指定路径接入、下载到目录、管 Isaac 镜像、填 RLinf 表单」都落不下去。

**C. 做成纯 RLinf 配置 GUI**  
丢掉编排、GPU 队列、日志采集。填完 YAML 自己 `docker run`。平台价值只剩表单，4 卡并发和历史任务会立刻回来成为问题。

采用 **A**：保留现行「容器化训练 + 调度 + 日志指标」的骨架，换掉领域模型和导航。
