11.2 五轮反思：还漏了什么

写画面之前把「会漏的」先列出来。每一轮都对照 02/03/09 与四个契约 YAML 复核过。

轮发现结论（写进本页）
1 契约页若只画「75 维一条向量」，WBC 的 +10 臂参考、双 action term、fixed-hand 的 concat:false 会再次被藏进 JSON。 四个契约各有一张「不规则点」卡片；详情默认打开 humanoid，可切换。
2 漏斗有两套真实数字：设计输入的 Ego4D 编译 155,369→35，与当前 scanner 的 manifests 17 文件 / 9 episode。混在一页会让人以为扫描坏了。 必须是两个 Dataset 实体。扫描页允许 0；禁止把 155k 当默认填充。
3 「配置」至少三层：平台设置、单次 JobSpec、本体环境 YAML。已发布环境不可改数字；草稿可改。 设置 ≠ 改已发布环境。详情页：active 加锁，draft 可编辑。见 12。
4 03.8 配额/GC、index 里的镜像能力矩阵、UDP 端口、固件关节数，从未进入任何表单。 设置·配额、设置·镜像、契约·真机绑定只读区。
5 空态比有数据更常见：无视频、403、扫描中、镜像缺失、G3 形状不符。空态若画成假图，检测时无法分辨。 每类空态有固定文案。缺媒体不绘制播放器皮肤。
第二轮之后又补上的遗漏 关节名必须按 YAML joint_order 列出（顺序错位是「动作看起来随机」的根因）； 频率条要能一眼看出 1/(sim_dt × decimation) == policy_hz； G3 矩阵的列是四个契约、行是已注册 ONNX，单元格写实测 shape 不是勾选幻想； Episode 的 playhead 必须同时驱动视频、关节曲线、距离曲线； 设置里的端口/EB_* 默认只读，改端口走 deploy/.env + 重启，避免 UI 改了容器没改。 另外：44 GB 全量 scan 会超时，所以设置必须有扫描根目录 / 超时 / 排除规则； 契约页要列出 YAML 里每条 assertions 的通过/失败，不能只显示一枚「自洽通过」徽章； MinIO 密码不进可写表单；时区固定 Asia/Shanghai 写在只读页。

Episode：三联联动与缺媒体

有媒体时（fixed-hand / 脚本专家）

  • 布局与同步规则见 03.6：画面 | 关节曲线（限位虚线）| 末端距离。
  • 一条 playhead：视频 timeupdate 写曲线竖线；拖曲线写 video.currentTime。
  • 只匹配文件名包含该 episode id 的视频；禁止用目录里另一个 mp4 顶上。
  • 视频走 ebd Range / 代理 H.264，不走 FastAPI 读盘。
  • 曲线按契约着色：10 条臂关节一组图例，可单独静音。

无媒体时（当前 ego 扫描常见）

缺媒体 没有视频文件，不渲染播放器外壳，不用纯色 canvas 占位。 若 parquet 有 action/state，仍画曲线与时间轴；两者都没有则只保留 episode id、校验结果、源路径。

Ego 长视频未生成 proxy 时，同样走这条空态，并提供「生成代理片段」Job，而不是卡在浏览器里 seek VP9。

11.9 需要你拍板的三件事

写设计时我按下面的默认值写了原型。若你要改，改的是默认，不是整章作废。
  1. 设置可写范围：默认「配额 / 通知 / 密钥」可写；端口、UDS、Redis、GPU 列表只读。是否允许在 UI 改 EB_PORT_*（仍要重启才生效）？
  2. 契约 YAML 全文：默认折叠只读，可视化为主。是否根本不在 UI 展示 YAML（只给 git 路径）？
  3. 漏斗数据集怎么命名：扫描仓与 Ego4D 编译仓是否保持两个 id（推荐），还是一个数据集两个 version 类型？
实现顺序建议（仍服从 10 章里程碑） 契约详情可视化 → 数据集概览统计 + 漏斗图落地（A 扫描数字）→ Episode playhead 同步 → 设置只读运行时 + 配额 → 切片/转换向导 → 提交表单命令预览。 先让「打开就能看懂身体和数据」，再做可写设置。
