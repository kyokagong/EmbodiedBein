## 已验证

- 受管资产 manifest 状态为 `verified`：训练与硬件 URDF 都是 23 个目标关节，两个资产各解析出 24 个 mesh，未缺文件。
- `eb/rlinf:rpo-v2-wbc` 镜像从当前本地 RLinf 内容哈希构建成功，补丁在镜像构建时应用并通过 Python 编译检查。
- 后端完整测试为 `301 passed`；Python `F/E9` 检查与 `git diff --check` 通过。
- Compose 配置可解析，模型和资产目录分别固定为 `/data/kk/models`、`/data/kk/assets`。
- 合成 MLP checkpoint 已在专用镜像内完成真实 Torch→ONNX→ONNX Runtime 导出，实测 I/O 为 890→23，最大绝对误差约 `8.2e-8`；同一随机权重 ONNX 在固定 MJCF 中完成一个 MuJoCo case，并因跌倒和跟踪误差被正确判为不合格。该检查只证明执行与拒绝路径，不是策略性能证据。

## 尚未宣称完成

- 当前执行环境无法连接 NVIDIA 驱动，因此没有生成 PPO 更新、checkpoint 重载、Isaac rollout 或已训练 ONNX 的成功证据。
- `asset-manifest.json` 中 `hardware_verified=false`。训练 URDF 与硬件 V2.0 URDF 的 effort、velocity 和部分角度范围不同；闭链方向、电机零位、编码器符号、急停和 50 Hz 时延必须在真机核验后才能发布真机匹配基线或解除部署门禁。
- P5 真机部署不在本次 P4 范围内，平台不会因此放行真机。
