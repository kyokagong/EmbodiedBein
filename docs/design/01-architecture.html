01 · Architecture

系统架构与技术选型

这一章回答三个问题：哪些代码用 Python、哪些用 Rust，为什么； 单机上到底跑几个进程、怎么通信；以及哪天要上多机时，需要改动的最小集合是什么。

1.1 架构原则

所有后续取舍都从这六条推导。它们按优先级排列，冲突时上位原则胜出。

  1. 可复现优先于可用性
    任何 Run 都必须能凭 code_ref + config_hash + data_version + image_digest + seed 五元组重跑。 做不到复现的便利功能宁可不做。
  2. 外部仓库只读
    平台绝不写入 /data/kk/Berkeley-Humanoid-Lite、/data/kk/RLinf、/data/kk/berkeley_ego_data。 这三个目录是事实来源，平台通过 git worktree 快照与只读 bind mount 使用它们。
  3. 执行一律容器化
    控制面永不在宿主直接 subprocess 跑训练。所有计算都是「镜像 + 挂载 + 命令」三元组， 这样单机 Docker 与未来 K8s 才可能是同一抽象的两种实现。
  4. 控制面无状态，状态在存储
    FastAPI 与 Rust 守护进程都可以随时重启；重启后靠 PostgreSQL 与容器 label 完成 reconcile。
  5. 热路径旁路
    指标、日志、视频、大文件绝不流经 Python 的请求-响应循环。它们走 Rust 数据面，Python 只处理元数据与决策。
  6. 安全默认拒绝
    涉及真机、删除、覆盖已发布产物的操作，默认需要显式人工确认；Agent 的权限是白名单而非黑名单。

1.2 六层职责

层实现职责明确不做失败影响
L5 交互 Vue 3 + TS + Vite
Pinia · Vue Router		 信息呈现、交互、可视化渲染；WebSocket 订阅实时流；本地视图状态 不做业务校验（只做输入体验校验），不直连数据库或 Rust 服务 无法操作，后台任务继续运行
L4 控制面 Python 3.11 + FastAPI
SQLAlchemy · Pydantic v2		 REST/WS 接口、鉴权、Job 状态机、DAG 编排、资源准入、契约校验、栈适配、Agent 编排 不做文件哈希、不解析 tfevents、不转码视频、不直接调 Docker API 不能提交/查询；已提交容器不受影响
L3 数据面 Rust（单二进制 ebd，多子命令）
tokio · tonic · axum · rayon		 容器生命周期、日志/指标采集与归一化、数据集扫描与校验、artifact 内容寻址与流式分发、时序读写 不做业务决策、不做鉴权策略（只校验来自控制面的令牌）、不落业务表 失去实时流与新任务下发；已运行容器（detached）继续，重启后 reconcile
L2 执行 Docker 容器 真正跑训练/评估/采集/编译的进程 不感知平台存在（除少量环境变量），保持「拿掉平台也能手跑」 单个 Run 失败，不影响其他
L1 存储与资源 PostgreSQL · Redis · MinIO · 段文件时序 · GPU · 数据盘 持久化与算力供给 — PG 挂 = 只读降级；Redis 挂 = 队列停摆；MinIO 挂 = 产物不可下载
L0 外部 两个代码仓 · 原始数据 · 模型仓 · 真机 事实来源 平台不写入（真机除外，且需物理确认） —
L2 的关键约束 「拿掉平台也能手跑」是硬要求。平台生成的命令行必须能被你直接复制到终端里执行—— 这既是调试手段，也是防止平台变成黑盒的保险。每个 Run 详情页都提供 「复制等价命令」 按钮，输出的就是 Adapter 实际下发的那条命令。

1.3 Python / Rust 边界

边界的判据只有一条：这段代码是在做决策，还是在搬运字节？ 做决策的归 Python（逻辑复杂、变更频繁、生态在此）；搬运字节的归 Rust（吞吐敏感、逻辑稳定）。

Rust crate 划分

Cargo workspace 下多 crate，但发布为单个二进制 ebd，通过子命令启动不同角色。 单机部署最忌活动件多，一个二进制 + 一个 compose 服务即可。

crate职责关键依赖为什么必须是 Rust（否则代价）
eb-core共享类型、事件 schema、配置、错误、CAS 寻址规则serde · thiserror · blake3/sha2—（库）
eb-runner容器创建/启动/停止/清理，GPU 与设备绑定，日志多路复用，退出码与 OOM 判定，宿主重启后 reconcilebollard · tokio常驻进程需长期稳定与低内存；日志需持续多路转发。Python 侧 docker-py 是同步阻塞模型，长连接日志流容易卡死线程池
eb-collector解析 TensorBoard tfevents（protobuf）、stdout 正则抽取、NVML/DCGM 采样；归一化为统一指标点并写入时序 + 推流prost · nvml-wrapper · notify训练中每秒可产生数百指标点，一次训练 tfevents 可达数百 MB；轮询解析在 Python 里会持续占用一个核并抖动
eb-scanner目录遍历、sha256/blake3 校验、格式嗅探（parquet/JSONL/pkl/npy/mp4）、ffprobe 调度、缩略图与雪碧图生成、统计聚合rayon · walkdir · arrow2 · image最直接的收益：44 GB / 18,974 文件的全量校验，rayon 在 96 核上可近线性扩展；Python 多进程要付序列化与内存复制代价
eb-artifact内容寻址存储网关：分片上传、HTTP Range、视频转封装为 HLS 片段、引用计数与 GC 标记axum · tower · s3(aws-sdk)视频拖动预览需要高并发 Range 请求；sendfile/零拷贝路径在 Python ASGI 下难以保证
eb-tsdbappend-only 段文件时序：写入、按 step/时间查询、自适应降采样、多 run 对齐memmap2前端一次对比 8 个 run × 20 条曲线 × 6000 步 = 近百万点，需要服务端降采样后再返回；纯 Python 查询延迟会到秒级
eb-probe硬件探测与容量估算：ebd doctor 输出 HostProfile（GPU 型号/显存/空闲/驱动/CUDA/NVLink//dev/dri/shm 上限）；为 Python 侧的准入判断提供实时底数nvml-wrapper · sysinfo与 eb-collector 共用 NVML 绑定与采样循环；每次调度决策前都要刷新，走进程内调用而非 shell 出 nvidia-smi 解析文本
eb-cliebctl：运维与救援命令（列容器、强杀、重放事件、校验 CAS、导出诊断包）clap平台自身出问题时的兜底手段，不依赖 Web 与数据库

Python 侧模块

决策与编排

  • api/：FastAPI 路由、依赖注入、鉴权、OpenAPI
  • orchestrator/：Job 状态机、Pipeline DAG 引擎、重试与补偿、幂等键
  • scheduler/：资源准入、队列、优先级、抢占、预算账本
  • contracts/：Embodiment Contract 加载与五卡口校验
  • lineage/：血缘写入与查询（Run↔Dataset↔Model↔Artifact）
  • capacity/：容量估算器——三层查询（实测/解析/目录）、按栈公式、估算凭据与降配建议

领域适配与智能

  • adapters/isaaclab_rslrl.py：JobSpec → train.py/play.py argparse + Hydra
  • adapters/rlinf.py：JobSpec → Hydra overrides + Ray 引导
  • adapters/lerobot.py：数据集读写与格式转换
  • adapters/deploy.py：PolicyBundle 组装与部署 YAML 生成
  • harness/：ToolBus（schema→权限→幂等→预算→dry-run→执行→整形→审计）、 Session/Turn 循环、工具注册表、磁带录制与回放
  • pluginhost/：插件加载器——manifest 校验、作用域化注册与自动回收、依赖注入
  • agent/：规则引擎、剧本、上下文构造、LLM 客户端、经验库
边界上的两个灰色地带 ① 数据集统计：轻量统计（计数、分组）在 Python + SQL 里做；重量统计（逐帧扫描、直方图）由 eb-scanner 产出物化视图，Python 只读结果。 ② 评估指标计算：成功率等由训练/评估脚本自己算并写入指标流，平台不重算；平台只做聚合与门禁判定（Python，逻辑多变）。

1.4 通信协议

链路协议为什么数据量级
浏览器 → FastAPIHTTP REST + WebSocket
内网默认不启 TLS；如需外网暴露，前置 Caddy 自动签证书		REST 做 CRUD 与 OpenAPI 契约；WS 做实时推送（任务状态、指标、日志、Agent 流式输出）元数据，KB 级
浏览器 → 媒体/大文件HTTP Range
FastAPI 经 /run/eb/ebd-http.sock 流式反代到 ebd		视频拖动、checkpoint 下载不应经过 Python 缓冲MB–GB
FastAPI → ebdgRPC over Unix Domain Socket
/run/eb/ebd.sock		单机免端口、强类型、可用文件权限做访问控制；无需 TLS 开销。两条通道都走 UDS，因此 ebd 用 host 网络也不影响控制面请求-响应，KB
ebd → FastAPIRedis Streams（不回调）解耦：Rust 不需要知道 Python 在不在。控制面重启后可从 last-id 续读，不丢事件事件，每秒数十–数百
ebd → 容器Docker Engine API（/var/run/docker.sock）——
容器 → 平台仅文件系统（无网络回调）关键决策：容器不主动上报，避免侵入训练代码。平台通过挂载目录 watch 文件变化来采集tfevents / 日志 / ckpt
平台 → 真机HTTP 拉取部署包 + 遥测 UDP 回传机器人侧主动拉包，平台不主动推；控制指令一律不经平台包 MB 级，遥测 KB/s
「容器不主动上报」为什么重要 这条决策让平台对 Berkeley 与 RLinf 的代码零侵入：不需要在 train.py 里插桩、不需要改 RLinf 的 MetricLogger。 代价是采集有 1–3 秒延迟（文件系统 watch + 解析），对训练监控完全可接受。 更重要的是：上游仓库升级时平台不会崩。

1.6 目录布局

平台自己的状态全部在 /var/lib/eb。这个目录可以整体打包备份，也是唯一需要配额监控的位置。 外部三个目录只读挂载。 

/var/lib/eb/
├── repos/                          # git worktree 快照，按 commit 检出，只读挂给容器
│   ├── bhl/<short_sha>/            # Berkeley-Humanoid-Lite（含 2 个子模块）
│   └── rlinf/<short_sha>/
├── runs/<run_id>/                 # 每个 Run 独占，容器唯一可写的业务目录
│   ├── spec.json                   # 冻结的 JobSpec（含解析后的完整命令行）
│   ├── cmd.sh                      # 「复制等价命令」的来源，可手工执行
│   ├── workspace/                  # 覆盖层：configs/ logs/ outputs/ 的可写投影
│   ├── outputs/                    # 采集器认领的产物（ckpt/onnx/video/metrics.json）
│   └── logs/{stdout.log,stderr.log,events/}
├── cas/<ab>/<cd>/<sha256>         # 内容寻址存储（MinIO 之外的本地热层）
├── tsdb/<run_id>/<metric_id>.ebts  # append-only 段文件
├── media/{thumbs,sprites,hls}/    # 缩略图、雪碧图、HLS 分片（可重建，不备份）
├── cache/{hf,pip,torch,uv}/       # 跨 Run 共享的下载缓存，显著缩短冷启动
├── datasets/<ds>/<version>/       # 平台生成的派生数据集（LeRobot 等）
├── bundles/<bundle_id>/          # PolicyBundle：onnx/jit/yaml/manifest/签名
└── secrets/                       # age/sops 加密，0600，仅 eb-api 可读

# 只读挂载（平台绝不写入）
/data/kk/Berkeley-Humanoid-Lite   # → repos/bhl 的 worktree 源
/data/kk/RLinf                    # → repos/rlinf 的 worktree 源
/data/kk/berkeley_ego_data        # 44 GB 原始数据，:ro
git worktree 快照的作用 提交任务时记录目标 commit，若该 commit 的 worktree 不存在则创建（git worktree add --detach）。 这样做同时解决三件事：① 你在开发目录里随便改代码不会影响正在跑的任务； ② Run 的 code_ref 是真实可回溯的；③ 容器拿到的是只读目录，杜绝 play.py 改写 configs/ 污染仓库。 子模块需 git worktree add 后再 submodule update --init --recursive，Adapter 负责这一步并缓存结果。

1.8 部署形态

部署只有一条命令：docker compose up -d。 平台自身的每一个常驻件（api、ebd、postgres、redis、minio）都是 compose 服务， 宿主上除 Docker 与 NVIDIA Container Toolkit 之外不需要装任何东西—— 没有 systemd 单元、没有宿主 Python 环境、没有单独起的 uvicorn。 前端 vue-tsc && vite build 的产物在构建镜像时就被拷进 api 镜像的 web/dist，由 FastAPI 托管，单端口对外。

在 compose 里刻意不在 compose 里为什么
api · ebd · migrate · postgres · redis · minio（+ 可选 caddy）任务容器（训练/评估/数据）它们生命周期由 Job 决定、数量动态、需要按 JobSpec 定制资源与挂载，属于「被编排对象」而非「服务」。由 ebd 通过 Docker API 创建
—任务镜像（eb/isaac-lab、eb/rlinf…）构建耗时几十分钟且体积巨大，用 make images 单独构建、按 digest 引用。compose 不该在每次 up 时碰它们
—robot-agent跑在机器人上位机，是另一台机器（见 07.6）
 
# backend/eb/api/app.py（要点节选）
from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles
from fastapi.responses import FileResponse

app = FastAPI(title="EmbodiedBein", version="0.1.0", openapi_url="/api/openapi.json")

app.include_router(api_v1, prefix="/api/v1")
app.include_router(ws_router)                      # /ws/runs/{id} 等
app.include_router(proxy_router)                   # /media/* /artifacts/* → ebd（经 UDS 流式转发，不缓冲）

# 前端资源：带 hash 的静态文件长缓存，index.html 不缓存
DIST = Path(__file__).parents[2] / "web/dist"
app.mount("/assets", StaticFiles(directory=DIST / "assets"), name="assets")

@app.get("/{full_path:path}", include_in_schema=False)
async def spa_fallback(full_path: str):
    # history 模式：非 /api、非 /ws 的一切路径回落到 index.html
    if full_path.startswith(("api/", "ws/", "media/", "artifacts/")):
        raise HTTPException(404)
    return FileResponse(DIST / "index.html", headers={"Cache-Control": "no-store"})
注意事项 ① 通配路由必须最后注册，否则会吞掉 API 路由。 ② 大文件转发要用 StreamingResponse + httpx.stream，并原样传递 Range / Content-Range 头，否则视频拖动会退化为全量下载。 ③ 需要 TLS 时不改代码，只需 --profile tls 把 compose 里的 Caddy 拉起来；单机内网默认省掉（ADR-10 的已知代价）。

安全说明：docker.sock 等于 root ebd 持有 docker.sock 意味着它实质拥有宿主 root 能力。因此： ① ebd 不接受任何来自外网的输入，只信任 UDS（文件权限 0660，属组 eb）； ② 容器创建参数由 ebd 内部按白名单模板生成，控制面只能传枚举值与受限字符串，不能传任意 HostConfig； ③ 禁止 privileged、禁止挂载 /、挂载路径必须落在允许前缀内。这三条要有单元测试守住。 整套系统里只有这一个服务有特权，这是把它单独拆出来的主要理由。
兄弟容器：为什么 /var/lib/eb 两侧路径必须一样 ebd 自己在容器里，但它通过宿主的 Docker 守护进程创建任务容器—— 这些任务容器是它的兄弟而非子进程。因此 ebd 传给 Docker API 的 -v 路径会被守护进程当作宿主路径解释，而不是 ebd 容器内的路径。 只要两侧都挂在 /var/lib/eb，ebd 看到的路径拼出来就是对的； 一旦改成 /data:/var/lib/eb 这种不对称写法，任务容器会挂到不存在的目录上， 且错误表现为「训练启动后找不到文件」而不是挂载失败，很难查。 这是 docker.sock 模式最经典的坑
两类网络模式混用的规则 ebd 用 host 网络，其余用桥接，所以同一个 Redis 有两种写法： 桥接侧是 redis://redis:6380（服务名 DNS），host 侧是 redis://127.0.0.1:6380（宿主 loopback + 映射端口）。 为了让这两个写法至少端口号相同，Redis 在容器内也监听 6380 而非默认 6379—— 否则会出现「桥接用 6379、host 用 6380」的双数字混淆，是无谓的记忆负担。
另外注意：api 不通过网络访问 ebd， 两条通道都是 UDS（gRPC 一个、媒体流一个）， 所以 ebd 换不换网络模式都不影响控制面。

1.9 失败模式与降级

故障直接后果降级行为恢复动作
ebd 崩溃/重启新任务无法下发，实时流中断已运行容器是 detached 的，继续训练不受影响；前端显示「采集中断」而非「任务失败」启动时按 label=eb.run_id 列出容器，重建内部状态表，从 tfevents 上次 offset 续读（幂等，指标不重复）

PostgreSQL 不可用元数据读写失败API 进入只读降级：可查缓存与实时流，禁止提交；调度器暂停出队PG 恢复后自动重连；runs/<id>/spec.json 是二级真源，可用 ebctl reindex 重建

备份与恢复：分清哪些丢了要命

单机部署没有副本，所以必须清楚每类数据丢失后的后果。 关键判断是：大部分体积能重建，少部分体积重建不了——备份只需覆盖后者。

数据体积量级能否重建备份策略丢失后果
PostgreSQL< 1 GB不能pg_dump 每日 + 每次 migration 前，保留 30 份最致命：所有血缘、契约、评估结论、审计全部消失。产物文件还在但不知道它们是什么
secrets/KB不能离线单独保管（不与主备份同处）需要重新配置所有凭据
tsdb/GB 级部分每周增量；tfevents 仍在 CAS 中，可重新解析曲线丢失但可从 tfevents 重建
cas/（模型、视频、数据）TB 级部分按内容分级：已发布策略包与基线模型必备；中间 checkpoint 不备丢中间产物可接受；丢已发布策略包则需重训
repos/（worktree 快照）GB 级能不备份从 git 重新检出即可（前提：commit 已推到远端）
media/ cache/GB–TB能不备份重新生成，仅损失一些时间
一个便宜且有效的组合 每天一次 pg_dump（几十 MB）+ 已发布策略包与基线模型的镜像副本， 就覆盖了 95% 的不可重建价值，总量可能不到 50 GB。 剩下的 TB 级数据即使全丢，也只是损失时间而不是损失知识。 把「重建成本」当作分级依据，比按目录一刀切备份高效得多。 另外：pg_dump 应写到与数据盘不同的物理盘，否则盘坏了备份一起没。

1.10 平台自身的可观测性

结构化日志

两侧统一 JSON Lines，共享 trace_id（HTTP 头透传到 gRPC metadata 再到容器 env）。 Python 用 structlog，Rust 用 tracing + tracing-subscriber。

自身指标

复用 eb-tsdb：API p95 延迟、队列长度与等待时长、容器启动耗时、采集滞后（lag）、CAS 命中率、磁盘水位。 「采集滞后」是最重要的健康信号。

诊断包

ebctl diagnose --run <id> 一键打包：spec、等价命令、容器 inspect、最后 2000 行日志、 GPU 快照、契约校验结果。用于向 Agent 或人求助时提供完整上下文。

1.11 单机 → 多机演进

当前版本明确是单机。为了让未来迁移不是重写，下面五个接缝从第一天起就要抽象出来。 其余部分允许写得「单机专用」——过早泛化的代价比迁移更高。

不要现在就做的事 多租户配额体系、跨节点数据本地性调度、镜像分发加速（p2p）、GPU 分时切片（MPS/MIG）。 这些在 4 卡单机上收益为零，且会显著拖慢 M1–M2 的交付。 唯一例外是 Executor 接口——它必须一开始就抽象，因为事后拆解成本极高。
