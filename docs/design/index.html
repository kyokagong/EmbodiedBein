EmbodiedBein · Design v0.1

把一个人的具身智能研发，
变成一条看得见的流水线。

EmbodiedBein 是一个单机部署的具身智能研发管理平台：统一管理异构数据、多种模型、两套训练栈、 仿真与真机评估，直到策略发布上机；并内置一个可自主闭环的 Agent 承担重复劳动。 它同时是你的工作台，也是同事理解你产出的窗口。

本体 Berkeley Humanoid Lite 训练栈 Isaac Lab+RSL-RL / RLinf 数据 44 GB · 18,974 文件 算力 4×RTX 4090 24G · 96 core · 125 GB 后端 Python+Rust · 前端 Vue 3

一、为什么需要这个平台

这套设计不是从「MLOps 平台该有什么」出发的，而是从你现有三个仓库里实际存在的失败模式倒推出来的。 下表每一行的左侧都能在代码或数据里找到出处，右侧是平台对应的机制。

现有痛点（有据可查）证据平台机制
本体维度矩阵极易静默出错
四套观测布局、三套自由度共存		 humanoid obs 75/act 22 @25Hz、biped 45/12 @25Hz、WBC 85/22 @50Hz（command_dim 13）、fixed-hand state 10/act 10 @20Hz。写错一处要等仿真起来几十分钟后才暴露。 Embodiment Contract 作为一等实体，在提交任务 / 注册数据 / 注册模型 / 导出 / 上机五个卡口做静态校验，秒级拦截。
训练任务互相污染仓库 play.py 会直接改写仓库内的 configs/policy_latest.yaml；训练默认写 logs/rsl_rl/<exp>/<timestamp>/。并发两个任务就会打架。 源码只读挂载＋每个 Run 独立 workspace/ overlay，输出全部重定向；产物再回收进内容寻址仓库。见 05·工作区隔离。
两套训练栈的配置语义完全不同 Isaac 侧是 argparse＋@configclass＋Hydra entry point；RLinf 侧是 Ray＋纯 Hydra YAML＋cluster.component_placement。人脑切换成本高、容易漏参。 统一 JobSpec ＋ 每栈一个 Adapter，把平台语义翻译成各自 CLI；命令行做 snapshot 测试防漂移。
数据可用性极低且过程不可见 Ego4D FHO 155,369 个候选事件 → 最终仅 35 个场景被接受（reach 29 / push 6）；TACO 2,212 与 goalstep 34,332 全部为 0。拒绝原因散落在 JSONL 里。 数据漏斗审计：每一级留存率、拒绝原因分布、可下钻到样本与视频；漏斗本身是可复现的流水线产物。
4 张卡会被抢爆 Isaac Sim 需整卡＋Vulkan；OpenVLA-7B 全参微调按公式算连 4 卡都放不下（需 LoRA 或 8-bit 优化器）。凭感觉估显存，代价是跑到第 8 小时 OOM。 容量估算器（实测>解析>目录，估算自带出处与降配建议）＋资源准入与队列：整卡为调度单位、独占/共享声明、排队与抢占。
产物散落，复现靠记忆 Isaac 产物在 logs/rsl_rl/<exp>/<ts>/，RLinf 在 logs/<ts>-<cfg>/<exp>/checkpoints/global_step_N/，导出物在 exported/ 与 configs/。 统一 Run / Artifact 注册，复现五元组：code_ref + config_hash + data_version + image_digest + seed。
sim→sim2sim→real 的一致性无人追踪 链路是 Isaac 训练 → 导出 ONNX → MuJoCo 验证 → UDP/CAN 上机，但三段之间的行为差异没有量化留档。 跨域一致性指标（L3）：同一策略同一 seed 在三域的动作/状态偏差与分布 KL，进入发布门禁。
数据许可有合规风险 Ego4D 为非商业许可、HOI4D 为 CC-BY-NC-4.0、TACO 为 CC-BY-4.0；HOI4D 部分资源当前处于 403 受阻状态。 数据集强制 license ＋ gate_status 标签，导出/分享/发布时按许可传染性拦截。见 03·许可与门禁。
磁盘一定会爆 仅原始数据 44 GB；Isaac 每 100 iter 存一个 checkpoint，一次 6000 iter 训练就是 60 个模型文件，再加视频。 配额与生命周期治理：top-k checkpoint 保留、视频降采样归档、水位告警与 GC 预演。
同事看不到你在干什么 进展分散在终端、TensorBoard、若干 Markdown 设计文档里，没有单一入口。 Showcase 叙事视图：血缘图、周报快照、只读分享链接，30 秒讲清「现在做到哪、下一步卡在哪」。

二、系统全景

六层结构。控制面（Python）负责决策与编排，数据面（Rust）负责高吞吐的采集、扫描与搬运， 两者以 Unix Domain Socket 上的 gRPC ＋ Redis Streams 通信；执行层一律是容器， 这样单机的 Docker 与未来的 K8s 只是同一 Executor 接口的两种实现。

三、端到端主干管线

平台的核心叙事是一条可复现、可门禁、可回流的主干管线。九个阶段各自是一类容器化 Job， 阶段之间靠 Artifact 与门禁连接，任何一段都能单独重跑而不破坏上下游的血缘记录。

三道门禁的意义 门禁不是流程官僚，而是把「本来要在真机上炸出来的问题」提前到几分钟内的自动检查。 A 拦维度/频率不匹配与指标不达标；B 拦导出物与契约不一致、校验和缺失； C 拦 sim2sim 行为漂移。三道全过才允许生成上机包，详见 07 · 三段放行流水线。

五、关键设计决策（ADR 摘要）

下表是十条会显著影响实现的决策。每条都给出被放弃的替代方案与代价， 以便日后条件变化时可以有依据地推翻，而不是重新猜。

编号决策理由放弃的替代代价 / 触发重议的条件
ADR-01控制面 Python，数据面 Rust编排逻辑变化快、生态在 Python；tfevents 解析、44 GB sha256、视频 Range 是 CPU/IO 密集，Rust 在 96 核上收益明确纯 Python（多进程绕 GIL）两套工具链与 CI；需要清晰的 IPC 契约。若数据量长期 <5 GB 则收益不明显
ADR-02Docker 直连，抽象 Executor 接口当前单机，K8s 会引入大量运维面；接口留口后迁移只需新增实现一上来就 K8s + Volcano失去 K8s 的调度器与故障恢复；多机时必须补 K8sExecutor
ADR-03Redis Streams 作队列已需 Redis 做缓存；Streams 有消费组与 ack，够用且可观测Celery / RQ / Kafka没有成熟的重试中间件生态，需自写补偿逻辑
ADR-04Artifact 内容寻址（sha256）天然去重与完整性校验；与 Berkeley 导出物已带 sha256 的做法一致路径寻址 + 数据库记 md5需要维护引用计数才能安全 GC
ADR-05时序先自研 append-only 段文件指标模型极简（run×metric×step×value），自研可控且零外部依赖直接上 VictoriaMetrics / Prometheus缺 PromQL 生态。触发重议：需要跨月长周期聚合或多机汇聚
ADR-06Embodiment Contract 为一等实体与全局门禁这是本领域最高频的静默错误来源，收益最大的一条把维度当训练配置的普通字段新增本体形态时要先建契约，前期略繁琐
ADR-07源码只读挂载 + per-run workspaceplay.py 会改写仓库内 YAML，必须隔离；同时保证复现直接 bind mount 可写仓库需要 overlay 或输出重定向补丁层，个别脚本硬编码路径要特殊处理
ADR-08Agent 分三层，Autopilot 带硬预算你要的是自动闭环，但 4 张卡经不起无约束探索单一全权 Agent实现复杂度上升；需要完整审计与回放
ADR-09真机需物理确认，平台不远程使能电机22 个电机 + CAN 总线，误触发有人身与硬件风险Web 一键上机牺牲便利性换安全，不可协商
ADR-10全部服务由一份 docker-compose.yml 拉起；前端打包进 api 镜像的 web/dist，FastAPI 单端口对外部署只有 docker compose up -d 一步；宿主除 Docker 外零依赖，重装机器十分钟可恢复宿主 systemd 起 uvicorn + Nginx 反代 + 独立前端容器失去 Nginx 的静态优化与限流（需要时用 --profile tls 起 Caddy 补）；改前端要重建 api 镜像
ADR-11Agent harness 内核自研（Python ~2000 行），插件范式借鉴 dsh/Cordis，协议层复用 MCP难的部分（护栏、审计、上下文构造）没有框架能代写；自研内核与领域对象同进程，调试路径最短；MCP 让工具可被外部客户端复用直接以 dsh 为地基；或用 LangGraph 等重框架会话循环、流式、schema 校验需自己维护；放弃 dsh 的插件生态（我们本就不需要编码 agent 的终端/文件能力）。详见 8.3
ADR-12Agent 无 shell / 无文件系统 / 无出网 / 无 SQL；一切动作经 ToolBus 单一收口封闭能力集自身即沙箱，无需进程隔离；护栏只写一遍且无旁路；审计天然完备、行为可回放给 agent 沙箱化的 shell 与文件工具Agent 无法处理工具表未覆盖的新情况——但这正是我们想要的边界。详见 8.4

24 GB 单卡是最强约束：OpenVLA-7B 全参训练（AdamW fp32）静态就需 30 GB/卡， 4 卡也放不下，只能走 LoRA；π₀ 级（~3B）更现实，8-bit 优化器下 2 卡即可。 Isaac Sim 必须独占卡与渲染设备。详见 4.4。

容器与依赖要点

  • Isaac 侧宿主环境 python >=3.11,<3.12、isaacsim 5.1.0、isaaclab 2.3.2、torch 2.7.0； 而训练容器内为 isaaclab 0.54.3 + rsl-rl-lib 5.0.1，两条线不一致，平台必须按镜像记录能力矩阵。
  • RLinf 基础镜像 nvidia/cuda:12.8.1-cudnn-devel-ubuntu22.04，按 BUILD_TARGET 分化（reason / embodied-maniskill_libero / embodied-robotwin …）。
  • 两个 Git 子模块（assets、lowlevel）必须 --init --recursive，否则任务必然失败——这是平台的前置检查项。
