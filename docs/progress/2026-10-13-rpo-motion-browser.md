# RPO 参考动作的数据页与可视化

日期：2026-10-13（Asia/Shanghai）。对照设计：数据与采集、工作台媒体边界，以及 BFM 参考先验与 G1 重定向设计。

数据列表可按“参考动作”搜索，并从 RPO BFM / UFO RobotState 数据集进入动作目录。目录展示片段 ID、来源组、train/validation/test 划分、频率、时长和有效帧。详情页不再将这两种动作格式显示成 0 episodes 或无机器人动作维。

可视化复用 URDF/STL 查看器与关节曲线：播放/暂停、速度、逐帧时间轴、关节选择、原始根位置、有效/拒绝帧及质量/来源信息。三维显示将第一帧水平位置归零，保留高度、根姿态和原始关节角；按名称映射关节，使用 wxyz 根四元数。不裁剪拒绝帧的角度，也不改变原数据的训练资格。

预览生成是 `data.convert` 的离线 CPU Job（1 CPU、2 GiB 主存、0 GPU），通过 Job/Run/ebd 执行。源目录只读；NPZ hash、展开大小、数组维度、有限值、时间轴与四元数均检查。JSON 预览及完整索引写入新 Run 的 `outputs/motion-preview/`，不写入原 Dataset。同版本重复提交复用任务，失败或产物丢失可重新生成；原始 NPZ 不由浏览器解析。ebd 仅按受控 Run/片段 ID 提供有大小上限的预览，API 按冻结索引和片段 hash 核对来源并要求鉴权。

## 多轮复核

1. **设计与数据语义**：区分动作片段和示教 episode；检查现有 30/70 片段的冻结版本、来源、划分、23 关节与根坐标。源目录及已发布数据不变；不把回放当成策略物理评估。
2. **保真、失败与边界**：检查名称映射、wxyz、完整时间轴、拒绝帧保留、NPZ hash/解压预算、路径穿越、索引失配、产物丢失、幂等与重试。真实提交暴露了容量估算器未登记 CPU 预览操作的问题；按现有 CPU 操作分支修复，保留零显存准入行为检查。
3. **页面与实际证据**：容器后端 40 项、前端 31 项、ebd 3 项测试通过，类型检查和 Vite 构建通过。真实 Chromium 检查网格加载、播放/暂停、时间轴、关节切换、列表/详情导航及未登录请求拒绝。截图复核修正了坐标组变换后首次取景的矩阵更新。测试浏览器使用 Xvfb/Mesa CPU WebGL，不占用训练 GPU。

部署使用 `make up`。未提交 Git，未启动训练或策略评估。回放范围是 `rpo_bfm_motion` / `rpo_ufo_robot_state`；旧 AMP NPY 与 G1 原始诊断格式不在本次回放范围。浏览器须支持 WebGL；不支持时显示查看器错误，关节曲线仍可查看。未验证手机端或 10 万 episode 性能目标。
