# 12 · 训练与评估环境目录、编辑和选择

## 目标与边界

环境作为左侧一级菜单，集中列出可用于训练、评估的运行环境。每项明确展示任务目标、奖励、失败条件、成功条件和实际绑定；训练与评估分别选择环境，再选择适配的模板或套件。环境页不能把本体接口、镜像、训练模板、评估套件当成同一个对象。

`EmbodimentEnv` 继续作为已发布不可变的观测/动作契约；`Task` 是行为身份；`EvalSuite` 是冻结的评估协议。新增 `EnvironmentProfile` 是面向操作者的环境版本，绑定一个本体接口和一个执行入口（训练模板或评估套件），并保存上述四类定义。一个 Profile 只有一种用途；同一行为的训练与评估 Profile 可以共享本体接口和任务。镜像/Doctor 保留在原 `/envs` 页面，通过环境页访问。

## 数据与生命周期

Profile 字段：`id`、`name`、`usage=train|eval`、`embodiment_env_id`、`task_id`、`template_id` 或 `suite_id`、`definition`、`status=draft|active|deprecated`、`revision_of`、`content_hash`。`definition` 包含 `task`、`reward`、`failure`、`success` 四段由实际绑定与参数生成的只读说明，以及 `settings`（仅受支持的可执行数值）。没有可核实资料时写“尚未定义”，不得凭猜测编造奖励或判据。

目录迁移为现有模板与套件建立 Profile；原模板/套件仍可被旧 API 使用。已发布 Profile 不原地编辑；“编辑”创建草稿修订，保存后显式发布。发布前后验证入口、本体接口、任务和数值范围。新 Job 持有提交时的环境 ID、修订内容和 hash；迁移前的旧 Job 保留原 spec，不回填虚假的环境版本。后续编辑不得重解释旧 Run、EvalReport 或改写冻结套件。草稿与废弃环境不进入新建作业选择。

## 实际生效与安全

训练 Profile 必须与所选模板的 `embodiment_env_id`、`task_id`、用途一致；评估 Profile 必须与所选 Suite 一致。编辑“任务”是改绑同本体接口、已验证的模板或套件，任务 ID 从入口派生；不能仅改文字冒充任务改变。后端在预览与提交使用同一个解析函数校验并生成快照，任务参数写入 JobSpec / EvalPlan；失配、旧修订、过期预览都拒绝。

首期可执行编辑范围：RPO 直立直行训练的前向目标速度、站立比例、速度跟踪与直立奖励权重；RPO `stand_walk` 评估的站立最大漂移与行走最小位移。前者在受管 RPO runner 中实际应用，后者传给评估 runner 的逐案例判定。安全跌倒阈值、终止惩罚、固定 seed 协议、正式套件、真机放行和本体接口不在编辑范围。其余模板/套件仅可改绑已验证的任务入口与名称；运行参数由固定 recipe/套件控制。说明文字只读并从绑定及参数重算，禁止把文字转换成任意命令、Hydra 键或执行代码。修改训练目标或奖励后产生新 Profile 修订；修改评估阈值产生独立诊断 Profile，不能冒充官方冻结 Suite 排名或验收。

RPO 执行参数代码打入任务镜像；部署更新时按仓库规定单独运行 `make images`，再运行 `make up`。未更新任务镜像的旧部署不得宣称新参数已生效。

## 页面与 API

- 左侧“环境”进入 `/environments`，按训练/评估筛选；列表显示名称、用途、任务、奖励、失败、成功、状态和绑定。详情页可查看修订及编辑表单；镜像与 Doctor 链接到 `/envs`。
- `GET /api/v1/environments`、`GET /api/v1/environments/{id}`、`POST /api/v1/environments/{id}/clone`、`PATCH /api/v1/environments/{id}`（仅草稿；只接受名称、绑定和受支持数值）、`POST /api/v1/environments/{id}/publish`。API 对只读 Agent 保持现有 ToolBus 限制。
- 训练页在模板旁提供兼容训练环境选择；评估页在套件旁提供兼容评估环境选择。切换模板/套件时重置不兼容环境。环境详情可带预选 ID 跳转新建页。
- 错误要说明字段、兼容关系和“仅描述/实际生效”状态；预览展示环境 ID、hash 与生效参数。

## 执行规划（按序，不跳步）

1. **现状与风险核对**：确认模板、套件、runner、JobSpec 与页面数据流；确认用户意图和本设计边界。
2. **数据与目录**：先写失败测试；增加 Profile 模型/迁移、种子定义、列表/详情/克隆/编辑/发布 API；检查旧数据与空定义。
3. **执行绑定**：先写失败测试；训练预览/提交和评估预览/提交共用校验，保存快照；接通 RPO 训练奖励/目标及诊断评估判据；检查模板/套件失配和旧修订。
4. **交互**：实现一级环境页与详情编辑；训练和评估分别选择兼容环境；检查空列表、草稿、切换模板、预览过期与错误显示。
5. **验证和多轮反思**：第一轮核对设计真源、不可变性和执行真实性；第二轮核对兼容性、数据迁移与历史任务；第三轮核对前端可用性、错误路径、测试/构建和无 git 操作。逐项修复发现的问题，再报告实际通过/未通过的检查。

## 验收

新环境页可看到所有已有可用模板和评估套件对应的环境及四段定义；可克隆、编辑、发布环境；训练/评估各自选择兼容的 active 环境。受支持数值在预览、作业快照和受管 runner 中一致；不受支持数值不能提交；历史运行不随修订变化。后端测试和前端构建通过。
